# 一键安装工具2.0：手机操作、Ubuntu执行

手机打开网页即可操作，同一份Go安装引擎负责检测、ADB配对、备份、安装、配置、验证和还原。支持Android与iPhone的现代浏览器；手机不需要安装ADB App，Ubuntu需保持程序运行。这里的安装是影院APK安装与配置，不刷写电视系统固件。

## Ubuntu开启手机入口

1. 将本次完整`linux-amd64`便携包复制到Ubuntu x86_64并解压，保留目录结构。
2. 在该目录运行：

   ```sh
   bash 启动手机局域网安装.sh
   ```

3. 程序显示局域网网址（默认端口18795）和8位手机连接码。手机连接同一局域网，在浏览器打开这个网址并输入连接码。连接码10分钟有效，最多每分钟5次错误尝试；已连接的浏览器会话可继续使用，Ubuntu程序重启后重新连接。
4. 保留Ubuntu终端运行。结束程序用该终端的Ctrl+C；不影响已装电视自行运行和原厂已保存的通电策略。

无桌面的Ubuntu或通过SSH启动时，推荐改用随包后台入口：

```sh
bash 后台启动手机局域网安装.sh
```

以普通Ubuntu用户运行即可，无需sudo。脚本显示网址、连接码、后台进程号和私有日志位置，然后返回。此后可以关闭SSH窗口或电脑，由Ubuntu继续运行，手机逐间操作即可。也可在本店已有的Cockpit网页终端执行此命令。先确认安装任务结束，再结束该进程；不重复启动占用同一份data的工具。

需要过期后重新连接的新手机，应在无安装任务时结束并重启入口，读取新的连接码；不要在运行任务中重启。已授权手机的本次浏览器会话不受连接码10分钟有效期影响。

多个网卡时可指定Ubuntu本机地址：

```sh
bash 启动手机局域网安装.sh --lan-ip=192.168.1.20
```

示例地址替换为Ubuntu实际局域网IP。程序只绑定指定的本机私网IPv4，不监听所有接口。不要将18795转发到公网；本入口用于可信酒店维护局域网。访客Wi-Fi隔离、Ubuntu防火墙或不同VLAN阻断时，应先按本店网络规则放通手机到Ubuntu及Ubuntu到电视的连接；本程序不自动修改路由、网卡或防火墙。

已有酒店继续使用原资料目录，避免另起一套PIN和备份：

```sh
HOTEL_INSTALLER_STATE='/已有酒店的私有data绝对路径' bash 启动手机局域网安装.sh
```

路径是本店自己的目录，不复制其他酒店data到新店。Ubuntu入口与电脑便携版不能同时打开同一份data执行任务；现有实例锁会阻止重复运行。

## 手机逐台安装

1. 打开“使用详解”里的连接方式，按电视／盒子／投影与具体品牌、型号查找开发者入口。
2. 在设备上开启实际可用的ADB／网络调试；首次授权框选择“始终允许”。在手机安装页填的是目标电视或盒子的IP，不能填成Ubuntu的IP。
3. 只有无线调试配对码的设备，在原页面查看配对端口和6位码，在工具完成配对后，再填无线调试主页面的连接端口。不能把两个端口混用。
4. 检测后查看验证级别和限制。本项目已验、上游方法、受控试装、已知失败、暂不支持分别显示；盒子方法按精确身份匹配，不按品牌全部放行。
5. 已先安装Ubuntu的酒店，从本店`/etc/hotel-tv/setup-credentials.txt`取得员工PIN，在工具选择“已有员工PIN”复用；没有现成PIN才生成并保存。后续复用同一份本店PIN。服务器可以稍后接入；现在接入时沿用现有后台登录、房号登记和逐台纳管流程。
6. 需要通电开机时，可勾选“对已验固件配置通电自动开机”。当前仅MiTV-ASTP0/mulan的PW01精确固件有原厂方法，其他型号跳过并提示，不将其标为已配置。
7. 一键安装后等待结果。不要在运行任务中关闭Ubuntu程序。手机页面重开后可查看本次运行状态；程序重启后保留的报告明确标为历史任务，不冒充仍在运行。
8. 自动检查完成后，到现场验遥控、HOME、声音、播放、待机；通电自动亮屏要真实拔电验证，不能用软件重启代替。

## 四种码的区别

| 名称 | 从哪里取得 | 用途 |
|---|---|---|
| 8位手机连接码 | Ubuntu当前安装程序终端 | 允许手机操作这次安装工具 |
| 6位ADB配对码 | 电视／盒子无线调试页面 | 授权Ubuntu与目标设备建立调试连接 |
| 本店统一员工PIN | 本店首次设置／原私有data | 电视员工维护，不用于连接手机网页 |
| 独立设备凭证 | 后台逐台登记／自动写入 | 电视接入本店服务，不应全店共用一个设备凭证 |

## 盒子与电视的差别

盒子没有电视面板的电源控制权限。盒子自动启动、HDMI-CEC开电视、电视原厂来电亮屏是三项能力，需要分别验。保持原影院界面和功能，不将别人的Launcher作为本影院替代品。

本版新增小米盒子、NVIDIA SHIELD、onn、Freebox等精确记录的guard受控试装；尚无本影院盒子实体验收。Google Chromecast／TV Streamer、Fire OS、创维P3特殊包名路线、腾讯Q5043等限制在方法库单列，不能把“能够连接”当成“可完整接管”。非Android平台不能安装本影院APK。

## 依赖与恢复

员工端仅需完整便携包与浏览器。Go程序、对应平台ADB、两种同签名影院APK、自有原厂电源helper、兼容附件和说明均随包；不需要Python、Java、Android SDK、JADX或Android Studio。JDK/SDK仅开发构建自有helper时使用。

本机`data/backups`和目标设备侧还原点沿用现有机制；恢复仍核对本台身份和原值。原来已是direct的电视不会在本次失败回退时被改成secondary。旧备份缺少通电原值时不推断；固件升级后不再匹配原厂电源接口条件时，该项明确未还原并需另验。

Windows/macOS/Linux本机便携入口继续保留，默认只监听127.0.0.1。新手机入口不要求已有Ubuntu影院后台在线，也不把服务器配置变成电视安装前提。当前Linux包为x86_64，Linux ARM设备需另备对应ADB并验证后才能发布，不视为本包已支持。
