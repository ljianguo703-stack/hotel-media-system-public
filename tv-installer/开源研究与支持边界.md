# 原生电视安装工具：开源研究与支持边界

研究日期：2026-10-28，Asia/Singapore。用户要求仅原生安装，保持现有影院电视界面与功能；不使用外接盒子。按平台交叉检索，不声称已穷尽全网。下面是方法依据，不是本影院跨型号验收报告。

## Android 系列

| 项目 | 可借鉴内容 | 本版处理 |
|---|---|---|
| [Aerial](https://github.com/pengchujin/aerial-tv) | standard/guard、无障碍守护、通知复活、厂商HOME属性、按品牌调试入口 | 延续现有影院已采用的守护，保留界面；安装器独立实现权限/检测/恢复，不停用原厂应用 |
| [CleanYourTV](https://github.com/Gathin23/cleanyourtv) | 分型号记录、系统差异、恢复与HOME陷阱 | 作为方法/限制来源；不执行其桌面替换或清理列表 |
| [CleanYourTV App](https://github.com/udhaykumarbala/cleanyourtv-app) | 身份匹配元数据、分阶段执行、无线调试说明 | 173份线上核对元数据经筛选导入，盒子/电视棒条目仅归档并禁止安装；元数据MIT许可及线上提交与原始快照保留在licenses；加本项目/已知限制共175条 |
| [tvhelper](https://github.com/wukongdaily/tvhelper) / [Docker版](https://github.com/wukongdaily/tvhelper-docker) | ADB依赖检查、连接授权、菜单操作、批量APK、电视信息与布局差异 | 借鉴流程组织；不执行它的在线脚本、不更换桌面、不装市场，也不采用其卸载后重装分支 |
| [TV Box Tools](https://github.com/smartago/tvboxtools) | 设置默认HOME后读回验证、保留原厂桌面和恢复 | 只借鉴验证原则；盒子不作为用户方案 |
| [Luncher](https://github.com/CVasilakis/luncher) | Google TV、Fire OS、Vega的差异 | Fire OS接管不能由侧载成功推断；Vega不视作Android |
| [Accueil](https://github.com/sway-agency/tv) | 安装次序与分品牌资料 | 不采用另一套电视界面 |
| [Android TV Developer Enabler](https://github.com/BuddhaYi/android-tv-developer-enabler) | 部分设备开发选项入口 | 仅候选资料；不打包未经本影院验证的开启器，不把安装开启器等同于取得ADB权限 |

机型匹配使用品牌、模型/设备代号、SDK；同时提供型号与芯片时两者都要匹配。有固件前缀限制的上游记录强制检查前缀，本店实测条目还匹配完整固件指纹。上游“tested firmware”原文随记录保留，但不宣称本工具已在该固件运行；安装仍须实际HOME检查和现场验收。无匹配停止。Android名为VIDAA_TV的固件与真正VIDAA OS按SDK/运行时区分。

已知不能一概安装：部分TCL MT9655固件只有TLS调试且无配对入口、也无无障碍设置；Aerial记录了只能装应用而不能接管的状态。部分Fire OS型号只有清理/普通侧载记录，不能据此宣称本影院开机/待机可用。品牌范围不覆盖其所有型号与地区固件。

## Samsung Tizen

- [quiet-tizen](https://github.com/jss8649/quiet-tizen)：原生NUI/.NET、SDB预检、备份/恢复和明确的固件边界。其主要现场记录为UN75U8000FFXZA、固件1300.9；公版通用脚本没有在第二台电视端到端重放。它不是通用安装器，不能直接运行Android APK，也不应换成它的界面来冒充保留现有影院。
- [samsung-tv-root](https://github.com/chris-ritsen/samsung-tv-root)：按平台/固件预检及会话清理；root取得不证明影院客户端/桌面可用。SDB另装且私有框架不能简单重分发。
- [TizenBrew](https://github.com/reisxd/TizenBrew)、[TizenBrewInstaller](https://github.com/reisxd/TizenBrewInstaller)、[社区包](https://github.com/Apps2Samsung/tizen-community-packages)：提供WGT/原生应用安装分发路径，年份/固件/签名限制不同。
- 本版状态：已找到原生路径，影院尚未完成Tizen原生界面、遥控、播放/广告、配置/设备鉴权和开机/待机移植，**暂不支持安装**。

## LG webOS

- [Dev Manager](https://github.com/webosbrew/dev-manager-desktop)、[ares-cli](https://github.com/webosose/ares-cli)：原生IPK安装、设备开发模式与管理；能够安装IPK不代表能运行影院APK。
- [RootMyTV](https://github.com/RootMyTV/RootMyTV.github.io)：固件敏感的Homebrew访问路径，不是所有LG电视都可用。
- [CleanYourTV-WebOS](https://github.com/lasharor/cleanyourtv-WebOS)：已root设备的桌面/恢复，webOS主版本和系统组件有限制。
- [无root版本](https://github.com/Razdva122/clean-your-tv-lg-webos)：Developer Mode和电视本机helper的路线；开发模式维持与网络权限仍是条件。
- [rawin-launcher](https://github.com/rawinek/rawin-launcher)：webOS4/10的不同实现和精确固件检查；[webos-launcher](https://github.com/partridgeworks/webos-launcher)、[Launch Home](https://github.com/gprot42/webos-launch-home)补充其他桌面/启动研究。
- 本版状态：有多条原生路径，但影院原生客户端与当前电视UI尚未移植，**暂不支持安装**。

## VIDAA、Roku、其他封闭系统

- [Stremio VIDAA侧载助手](https://github.com/Stremio/stremio-hisense-install)、[VIDAA适配分支](https://github.com/kimkha/stremio)：Web应用注册/HTTP-DNS辅助手段，部分新固件/投影返回成功却不注册图标；本工具不改路由DNS，不把浏览器书签当作原生接管。
- [Roku官方样例](https://github.com/rokudev/samples)、[官方开发模式说明](https://developer.roku.com/dev/docs/developer-setup)、[Roku Dev Studio](https://github.com/paramount-engineering/roku-dev-studio)：BrightScript/SceneGraph与开发侧载可研究，需要影院独立实现，开发侧载有槽位与账号约束。
- HarmonyOS、荣耀封闭固件、Vega、Titan、SAPHI及其他平台：本轮没有完成保持当前影院全部功能的可重复原生安装证据，均列**暂不支持**，不按品牌猜测底层系统。

## 依赖与后续扩展

旧版仅在APK里保存的默认连接/PIN，升级时只补电视设置的缺失项，不覆盖已保存值；可覆盖APK哈希清单阻止未知新客户端被旧包覆盖，后续广告等功能合并后须重建安装包。

本版运行时只需要随包ADB、两种影院APK和Go程序，系统浏览器与常见OS库由电脑已有环境提供。ADB从[Android官方Platform Tools](https://developer.android.com/tools/releases/platform-tools)下载；包内包含NOTICE、版本、下载归档SHA256和全文件清单。生产签名私钥不进入分发包，生产默认凭证不进入APK。

下一平台开放安装至少需要：该平台原生客户端保持现有影院UI、设备鉴权/配置/统一PIN、遥控与焦点、点播/频道/广告、开机/待机/断网恢复、备份与恢复，以及对应真实型号/固件的端到端记录。只把系统名字加入列表不构成适配完成。
