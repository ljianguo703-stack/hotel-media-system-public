# 一个包升级到最新统一版

当前统一升级文件：`hotel-tv-upgrade-latest.deb`，目标 `v1-0-0-rc5-in20u2`。u2修复严格umask下程序目录权限，保留IN20的菜单与业务功能。新Ubuntu首装IN20后已具备同样业务功能，无需为修订号再做一次升级。

## 已有影院只上传这一个文件

1. 保留本店备份，在维护窗口登录管理员后台。
2. 原后台点击“软件与更新”；A版后台进入“服务器与应用 → 软件与更新”。
3. 上传 `hotel-tv-upgrade-latest.deb`。目标选择“本机 Ubuntu”，核对后确认安装。
4. 在“安装任务”查看“酒店影院自动直升”的结果。升级后在“已核验版本”找“酒店影院系统”，应显示 `v1-0-0-rc5-in20u2`，并能看到A版菜单与运行概览。

不用选择from-pl04/from-rq04等不同ZIP。执行器 `hotel-tv-install-agent 1.0.0~rc5.in17` 是另一个组件，其版本号不是影院版本，也不代表本次后台升级失败。

## 自动识别与保留范围

支持PL04、RQ02、RQ04、RQ04u1、IN20、IN20u1及旧IN20各from版本。安装时读取Ubuntu当前实际release目录，为该起点生成严格匹配的内部更新清单，沿用现有部署锁、数据库备份、健康检查和失败回退。未知起点会先停止操作并报告版本，不覆盖未验证的部署。

只更新109个影院程序文件；影片、本店账号/PIN、设备配置、下载器、容器、网口和原备份不重置。电视APK和电脑施工工具分别管理，不随服务器升级自动推送。

## 失败或重复安装

若此前使用IN20u1提示启动失败且已恢复旧版，重新上传这份u2文件并新建安装任务。文件名相同，但SHA256和目标版本不同；不要对原u1任务点“手动重试”。u2可接续APT中未完成的u1配置，无需先强制清理dpkg。

若新程序启动失败，恢复原程序和业务数据库，“自动直升”任务会记录恢复结果。修复现场依赖/空间等原因后，可用同一个DEB重新上传或重试，检查新任务结果。后台提示已核验安装同一DEB时先查看“酒店影院系统”实际版本，已是目标则无需重装。

后台短暂断开后重新登录或刷新。不要把全新Ubuntu首装.run当升级包覆盖已有服务，不要反复尝试不同base的旧ZIP。

## 本次修复与验证

u1在root:root、umask 0027环境中创建的发布目录为0750，hotel-tv服务用户无法进入，systemd报告200/CHDIR。u2在停服务前将新发布程序目录明确设为0755、程序文件0644；数据库备份仍为0600，不放宽配置、业务数据和恢复副本权限。

10项直升专项、安装器83项、软件管理17项通过。隔离Ubuntu使用原IN17执行器、真实HTTP上传/排队、真实APT和dpkg/postinst，服务以非root且空附加组运行，先降权限再进入工作目录。PL04直升通过；保留RQ04源码起点先复现u1权限失败及回退，再验证u2启动失败回退、同包重试成功及重复安装。配置和影片哈希不变，数据库使用原服务UID。

systemctl由隔离进程夹具接管，APT测试禁用网络且Python依赖已预装；这不是公司现场systemd升级验收。现场只读日志确认权限根因，当前RQ04服务正常；本轮未执行现场安装。原u1已撤回公开下载，由u2替代。
