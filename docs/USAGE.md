# 酒店影院日常使用教程 · IN20

一台 Ubuntu 服务一家酒店。电视和已下载内容在局域网运行；公网用于下载、维护和单独配置的住客留言入口。

## 登录与首页

浏览器访问 `http://服务器IP:18791`，使用本店后台账号登录。初始资料由首装生成，在服务器受保护文件中查看；不要把本店凭据复制到通用安装包。

默认进入“运行概览”。设备表只列当前在线且未停用、未归档的电视，不显示离线记录；需要维护完整设备清单时进入“电视与客房 → 客房设备”。房号、设备组、IP、本次上线时间、在线时长、当前接收/发送速率和今日累计量在同一行，手机端自动改为信息卡。可按房号、IP、设备组筛选。

“在线”表示最近 120 秒收到真实片库、广告、消息或维护心跳请求，不等于正在播放影片。上线时间从本轮采集到的在线会话开始，连续请求间隔不足 120 秒时保持；超时重连或连接 IP 变化会开启新会话。刚升级且尚无会话采样时显示待采集，不把旧心跳时间充当上线时间。

服务器卡片显示内网访问 IP、CPU、内存、媒体目录所在文件系统占用及主机连续运行时间。CPU 首次需要两个样本；后台服务重启不会把主机开机时间归零。系统不提供采集能力时显示不可用，不显示模拟值。

## 流量怎么读

- 顶部“服务器网口总发送/接收”和网口图：来自 Linux 网口计数，是该网口全部业务流量，包含下载器、后台访问和其他服务。直接点网口名称切换；发送、接收、IP、链路速度、双工和趋势同步改变。不把不同网口的转发流量简单相加。
- 设备表“影院业务流量”：只统计本系统对已认证电视实际读写的 HTTP body，含影片、广告、字幕和业务 JSON，不含其他电视应用、HTTP 头及网络协议开销。电视接收对应服务器发送，电视发送对应服务器接收。
- 速率单位 Mbps，累计单位 B/MB/GB。后台每 5 秒读取，主机每 2 秒采样；图保留最多约 15 分钟。首次采集时先等待样本，空白或“—”不代表 0。
- “今日”按后台业务时区分桶，只包含启用采集之后已记录的时段，不补造升级前的历史。更改时区会使用独立统计分桶；进程异常终止可能丢失最后约 2 秒尚未落盘的计数。
- 流量计数和在线会话存于数据目录 `runtime-metrics.sqlite3`，随程序更新保留。业务数据库备份主要保护账号、片库、广告、配置与留言，流量历史单独保留最近 7 日，不作为广告计费或审计凭证。

## 菜单与设置查找

左侧按工作台、片库与下载、电视与客房、广告经营、服务器与应用、系统设置分组。点模块展开二级入口，底部“设置中心”位置固定。顶部搜索或 `Ctrl+K` / `⌘K` 可按功能、旧菜单名查找；“NAS”“管理中心”“密码管理”“中插”等均能找到相应入口。

“设置中心”集中列出账号与安全、电视与播放、片库与存储、连接与远程、备份与维护、基础与记录。它是入口索引，同一功能保留一个业务归属；进入后仍使用原来的业务表单和保存校验。“全部功能”展示当前角色可访问的目录，星标可固定常用入口，收藏仅保存功能ID，不保存密码。

## 片库与下载

1. 在“加片与下载”搜索影片，使用现有下载器与媒体自动化工具。需要 TMDB、字幕或下载器连接设置时进入相应连接与策略区。
2. 已有影片可从“影片接入与扫描”接入挂载目录；扫描更新索引，不搬动原视频。Jellyfin 连接与周期统一从“Jellyfin 同步”进入。
3. 在“待上架”核对片名、海报、分类和分集，确认兼容后上架。缺失文件、兼容任务或下载失败进入对应检查和任务中心处理。
4. “影片片库”继续支持批量、置顶、归档、冷门清理等原有操作。分类排序与别名在“分类管理”；归档恢复在系统设置的回收站。

## 电视与客房

“电视首页与指南”管理首页入口、背景、二维码和只读酒店图文指南；“专题管理”“频道与节目单”分别管理专题与频道排期。电视首页仍沿原来的播放和遥控流程运行，本轮不改电视视觉风格。

“客房设备”登记本店电视、唯一房号和设备凭据。“设备分组”用于本店楼层或用途，不表示多酒店。“批量运维”使用现有纳管、诊断、任务和空闲升级机制；断网或正在播放时按原规则等待，不强制中断住客。

## 观众扫码留言

管理员进入“电视与客房 → 观众留言”。填写留言域名或公网 IP，可带端口；域名省略协议默认 HTTPS，IP 省略协议默认 HTTP，显式 HTTP/HTTPS 均按实际入口配置。开启前必须准备真实可达的入口。

本地访客监听只绑定 `127.0.0.1:18792`；公网服务器/NPS 按已配置的独立转发规则访问这个监听，不能把管理后台端口公开给住客。云端域名、TLS 和转发不由本次首装猜测或自动创建。未配置时留言保持关闭，店内播放不依赖公网。

设置提示文字、首次显示、重复间隔和每次时长后保存。电视 code18 按真实观看时间显示提示，暂停、广告、菜单、后台和待机时保持原门控。手机提交后，后台查询并将留言标为待处理、处理中或已处理；网络失败应保留输入并重试。留言、QR和地址规范化已纳入本版，无需另装 RQ02/RQ04。

## 广告经营

依次维护广告主、素材、套餐、投放单和广告任务，广告总控与播放规则统一归广告经营。开屏、片前、中插、暂停等触发规则与任务排期分别配置；日期、时区、客房组、小时上限与旧客户端兼容限制继续生效。

投放报表从原电视事件汇总，展示量不是收入。编辑套餐不会悄悄修改已有投放单的历史快照；套用新套餐需明确操作。商户报告仍从原报表入口查看和导出。

## 服务器与应用

文件中心、硬盘管理、容器管理和 Jellyfin 分别打开 File Browser、Cockpit、Dockge 和 Jellyfin 原生界面，不再建另一套管理能力。电脑共享、应用部署、NPS 穿透、端口与公网入口、软件与更新和任务中心分别归入服务器模块。

外部应用入口缺失时，管理员到“端口与公网入口”配置当前服务的实际地址；没有自动使用猜测地址。远程不可达不影响本店片库和已下载内容播放。硬盘操作继续遵守先备份和核对盘号，不通过本页格式化未知磁盘。

## 账号、密码与恢复

“系统设置”提供酒店与时区、账号与权限、密码与电视 PIN、数据库备份、配置历史与恢复、操作审计和回收站。密码入口使用现有 Ubuntu 身份验证，留空不修改。新施工优先复用本店既有员工 PIN，不为消除工具提示重新生成。

管理员、运营人员、只读账号仍沿原权限：管理员入口对其他角色隐藏，服务端继续鉴权，收藏和搜索不会提升权限。配置恢复与数据库恢复范围不同，操作前先看差异并保留现有数据副本。

## 电视施工工具 2.0.4

四平台完整工具均内置标准/守护 TV `0.1.17/code18`，保留 2.0.3 的缺项说明：缺现有 PIN、纳管房间名、精确设备检测或后台登录时，按钮旁明确提示原因；只有实际任务运行时才显示等待状态。选好已有员工 PIN、唯一房号和原应用类型后施工，按精确机型策略验收；标准与守护不可随意互换。

工具资料目录按本店分别管理，不自动合并包旁 data 和既有本店资料。保留原工具和数据，安装后逐间核对遥控、播放、声音、字幕、待机及通电恢复。未知机型、实体开关电源和目标房数长期并发仍需现场验收。
