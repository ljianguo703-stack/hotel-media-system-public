# IN20 升级说明

电视施工修订（2026-11-10）：2.0.7/code20覆盖已绑定却缺失窗口事件及HOME广播时的精确小米固件回退，固定资料路径避免换包丢失本店PIN和缓存。成品实机结果见同次验证记录，M1异机、实体电源和业务范围分别验收。后台IN20u2、固定首装和依赖不变。

## 版本组成

- 服务器与后台：`v1-0-0-rc5-in20`。
- 当前施工客户端：`0.1.19/code20`，既有签名标准/守护应用；固定IN20首装仍内置code18。
- 四平台施工工具：`2.0.7`，内置code20，并保留授权分类、电视还原点入口与独立ADB生命周期。
- 基础容器：复用既有 14 份固定镜像和原生依赖，未升级镜像版本。

## 新增与整合

1. A 版分组侧栏、固定设置中心、全部功能目录、旧名称搜索与常用入口。41 个入口映射到原页面/表单/应用，管理中心标签按业务归属收拢，原权限与旧链接保留。
2. 默认首页增加真实在线设备、IP、本次上线/时长、影院业务流量、Linux CPU/内存/开机时间/磁盘和网口流量趋势。离线设备不占首页，未采集数据明确显示等待或不可用。
3. 直接纳入 RQ02/RQ04：扫码留言、观看提示时序、后台处理队列、域名/IP/端口规范化、HTTP/HTTPS Cookie兼容。新首装不再要求安装后补 RQ02 或 RQ04。
4. 纳入 r4 Seerr 初始化密码修复、固定依赖与预载 aria2 检查；保留 DOC04 的国内/海外/本地安装、TMDB 和存储切换内容。
5. 纳入 TI21 工具缺项说明：已有 PIN、房间名、检测与连接条件清楚可见；工具四平台内置最新 code18。

## 安装与升级

全新 Ubuntu 使用本版一键首装和配套工具。已有服务器统一使用 `hotel-tv-upgrade-latest.deb`，安装时自动识别已支持的当前版本，详见 `docs/UPGRADE.md`。首装入口不作为已有服务的升级方式。

本轮没有自动升级任何酒店或电视。程序升级沿既有执行器先校验、备份、切换、健康检查和失败回退；影片、现有配置、账号、PIN和业务数据库保留。当前不再要求用户按起点选择不同ZIP。

## 统计口径与边界

设备只统计已认证影院 HTTP body；网口统计整机真实网口总量，两者不可直接等同。首次启用不补造历史，上线会话从首轮有效心跳开始。采样无需特权，不加抓包、监听端口、防火墙规则或云端服务。

本地流量历史独立保存，最近约 15 分钟趋势在内存中，日累计保留 7 日。业务备份与统计历史分别说明，统计不作为广告计费依据。

## 验证声明

验证以同次发布的校验清单和测试结果为准。隔离 Linux 的真实采样、协议流量、全功能入口和升级/回退，与酒店新机整装、24小时连播、实际150路容量、实体电视电源行为分开记录，不把旧 r4 的现场成功冒签为本版现场成功。
